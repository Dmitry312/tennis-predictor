# Player identity

CONFIRMED: PostgreSQL has match_id (internal match UUID), nbbet_match_id (source MATCH ID), championat_match_id (all NULL here), and player1/player2 display names. None is a source player ID. [Model](../../../src/tennis_predictor/storage/models.py), [UUID5 source mapping](../../../src/tennis_predictor/ingestion/nbbet/pbp_parsing.py) and every coverage-row matches.json are evidence.

Five details rows have players_json, e.g. [00014491 nbbet_details](../data_catalog/samples/match_00014491-b904-5816-bd67-b8d6226351d7/nbbet_details.json). p1/p2 identify match sides; nested "1" is name, "2" photo URL or NULL, "3" boolean of UNKNOWN business meaning, "4"."1" ranking number and "4"."2" ATP/WTA label. Raw match["3"]/["5"] preserve the same objects in all five raw examples. Numeric photo path segments and file names are media references, not demonstrated player IDs. Countries, birthday, hand, height and ranking points are not explicit player attributes in these observed objects. Do not decode flag/country from media URLs.

CONFIRMED: 40 distinct names in 20 PG rows, 10 nested player objects in five snapshots. Their names agree with PG side order. Both Latin and Cyrillic names occur, but no repeated person is established across matches/years; transliteration aliases and collisions remain UNKNOWN. Within-source duplication of the same name in raw/details is one upstream observation, not independent identity corroboration. Raw descriptive HTML may contain fuller names, but parsing prose is not a stable identity proof.

The previous [identity evidence](../identity-audit-evidence.md) found no stable ID in a different bounded scan, with invalid JSON/schema gaps. This catalog supports the narrow name/photo/rank observation, not an assertion that no source ID exists anywhere. Four newer details rows lack players_json despite PG details_version=3: version on PG describes latest processing, not necessarily this selected sibling object's schema.

[player_identity.py](../../../src/tennis_predictor/ml/player_identity.py) is aligned with this uncertainty: internal creation-event IDs, conservative NFC/lower/space aliases, no transliteration/fuzzy merge, name-only results provisional, ambiguity quarantined. Preserve that behavior. Proposed players use internal UUID; aliases require source path, side, validity/availability, evidence status and registry revision. Photos/ranks are supporting observations only. Need repeated named participants with independent stable links across years and homonym cases before asserting reliable longitudinal linkage.

Ancillary popularMatches repeats some display names (e.g. Swiatek I.) but references different, later matches. This is not a repeated audited participant and cannot validate cross-year identity. Swiatek media URLs differ between Juvan raw/details and the recommendation in Noskova raw, so even matching name/folder does not establish immutable media identity. The all40-distinct statement applies strictly to the20 PG match participants, not every name string in raw page recommendations. Logo-associated booleans may be presentation flags (INFERRED), never countries or source IDs.
